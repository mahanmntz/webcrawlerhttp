✔ معماری کامل توزیع‌شده با ۴ فاز عملیاتی

مرجع جامع و داشبورد تعاملی کراولر وب سازمانی

آموزش دقیق، راست‌چین و عمیق سیستم کراولر توزیع‌شده مبتنی بر فصل ۹ کتاب Alex Xu؛ تحلیل خط‌به‌خط دستورات، معماری همروندی Go، پارسر BeautifulSoup پایتون، API Gateway تایپ‌اسکریپت و صف‌های اتمیک Redis.

🌟 هدف کلان سیستم کراولر چیست؟

هدف ما ساخت سیستمی است که دقیقاً مانند موتورهای جستجوی عظیم (Google, Bing) عمل می‌کند: دریافت یک آدرس وب ریشه (Seed URL)، باز کردن و دانلود خودکار آن، کشف تمامی پیوندهای خروجی، و بازگشت پیوندها به صف کراول برای شخم زدن پیوسته تارنماهای وب.

🎯 ۳ چالش بنیادین در طراحی کراولر توزیع‌شده (فصل ۹ Alex Xu):
۱. جلوگیری از حلقه‌های نامحدود و صفحات تکراری (Deduplication): با دستور اتمیک SADD frontier:seen در Redis، هیچ لینکی دو بار کراول نمی‌شود.
۲. رعایت ادب و عدم تخریب سرور مقصد (Domain Politeness): با قفل موقت SET politeness:host:<d> NX PX 1000 مانع ارسال سیل ریکوئست‌ها به یک سرور می‌شویم.
۳. جداسازی کار شبکه از پردازش سنگین (Decoupled Scraping): عملیات سبک I/O دانلود شبکه در Go، و پردازش سنگین CPU-bound کالبدشکافی DOM در Python اجرا می‌شوند.

نقش هر فناوری در مونو-ریپو:

فناوری مسیر کد در ریپو وظیفه در سیستم چرا این تکنولوژی انتخاب شد؟
Redis 7.2 infrastructure/redis/ ستون فقرات پیام‌ها و فیلتر تکرار عملیات اتمیک بدون قفل دیتابیسی زیر ۱ میلی‌ثانیه؛ لیست‌های مطمئن BRPOPLPUSH.
Go (Golang) services/crawler-engine/ موتور دانلود سریع صفحات مدیریت همروندی با Worker Pool و استفاده مجدد از کانکشن‌های TCP با Connection Pooling.
Python 3.11+ services/parser-scraper/ پارسر DOM و کشف پیوندها کتابخانه فوق‌العاده استاندارد BeautifulSoup، نرمال‌سازی پیوندها و اعتبارسنجی با Pydantic.
Node.js / TS services/api-gateway/ ارکستراسیون جاب و API Gateway فریم‌ورک فوق‌سریع Fastify، اعتبارسنجی Schema ورودی و پایش زنده متریک‌های کلاستر.

🔍 فرهنگ لغت جامع دستورات (Command Dictionary)

تمام دستورات ترمینال از فایل Makefile ریشه پروژه می‌آیند. روی هر کارت کلیک کنید تا دستور خام، محل تعریف و چرایی استفاده از آن را با جزئیات کامل ببینید:

make cluster-up
بیلد و اجرای هم‌زمان تمام ۴ کانتینر در داکر کلاستر
make submit-job
ثبت آدرس اینترنتی جدید برای کراول از طریق API Gateway
make get-metrics
دریافت آمار زنده و طول صف‌های ریدیس از طریق Fastify
make get-docs
مشاهده اسناد نهایی تمیز استخراج شده توسط پایتون
make test-all
اجرای هم‌زمان تمام تست‌های واحد Go، پایتون و تایپ‌اسکریپت
make cluster-down
خاموش کردن امن و تمیز کانتینرها بدون از دست رفتن داده‌ها
🚀 دستور make cluster-up:
فایل docker-compose.yml را می‌خواند؛ کانتینرهای Redis، API Gateway، موتور Go و پارسر Python را بیلد کرده و روی شبکه ایزوله crawler-net در بک‌گراند اجرا می‌کند.
# دستور اجرا شده در شل: docker compose up -d --build # محل تعریف در ریپو: # Makefile: خط ۳۶ (cluster-up)

🔄 سفر ۹ مرحله‌ای یک لینک در سیستم (چرخه بسته)

ببینید چطور داده‌ها میان Fastify، Redis، موتور Go و پارسر Python دست‌به‌دست می‌شوند:

  • ۱
    ورود آدرس به سیستم (Client Request)

    کاربر آدرس https://news.ycombinator.com را با متد POST به /api/jobs ارسال می‌کند.

  • ۲
    فیلتر تکرار در گیت‌وی (Seen Filter Check)

    سرویس Fastify دستور SADD frontier:seen را در Redis اجرا می‌کند. اگر آدرس تکراری باشد بلافاصله ارور ۴۰۹ می‌دهد؛ در غیر این صورت ادامه می‌دهد.

  • ۳
    صف‌بندی تسک در ردیس (Enqueue CrawlTarget)

    تسک طبق قرارداد crawl_target.json با شناسه UUID بسته‌بندی شده و با LPUSH frontier:queue ذخیره می‌شود.

  • ۴
    برداشت مطمئن توسط موتور Go (Reliable Dequeue)

    ورکر Go تسک را با BRPOPLPUSH frontier:queue frontier:processing برمی‌دارد تا در صورت کرش، تسک هرگز گم نشود.

  • ۵
    بررسی قفل ادب دامنه (Politeness Lease)

    موتور Go بررسی می‌کند آیا اخیراً به این دامنه متصل شده است یا خیر (SET NX PX). اگر دامنه خنک بود، دانلود را آغاز می‌کند.

  • ۶
    دانلود بهینه و انتقال به صف خام (Fetch & Push RawPage)

    صفحه با کلاینت بهینه‌شده Go دانلود شده و پیلود خام HTML به صف queue:raw_pages منتقل می‌شود.

  • ۷
    برداشت توسط پارسر پایتون (Python DOM Extraction)

    سرویس پایتون صفحه را از صف کشیده و با BeautifulSoup عنوان، توضیحات متا و لینک‌های صفحه را استخراج می‌کند.

  • ۸
    استانداردسازی پیوندها (URL Canonicalization)

    پایتون لینک‌های نسبی را مطلق می‌کند، فرگمنت‌ها (#) را حذف کرده و پسوندهای عکس یا اسکریپت را فیلتر می‌کند.

  • ۹
    بستن چرخه: تزریق لینک‌های جدید به صف اول (Closed Loop Re-enqueue)

    پایتون لینک‌های کشف‌شده را دوباره با frontier:seen چک می‌کند و لینک‌های نو را با depth: 1 به صف Go برمی‌گرداند!
